# 当前实现状态与后续重点

## 当前阶段

项目当前使用“三张角色构筑 + 一张通用祝福、四选二”的普通升级体系。每个角色 6 个技能构筑单独派生等级，首次达到 Lv.3 后进入专属二选一质变。

## 已具备内容

- 主菜单、存档选择、无尽模式、暂停菜单、HUD、角色面板和开发者模式。
- 三角色战斗：剑士、枪手、术师。
- 自动攻击 / 鼠标跟随攻击模式。
- 普攻、后台攻击、切人、大招、技能冷却栏。
- 构筑四选二升级、单卡刷新、18 个技能构筑等级、36 个互斥质变、祝福等级和当前技能解锁链路。
- 小 Boss 装备奖励、装备持有和角色间转赠。
- 地图边界内波次刷怪、刷怪警告、难度 profile、性能保护、高密度战斗性能证据门禁、新怪入场削峰队列、默认启用的敌人/敌方弹幕/掉落物批处理，以及可手动开启的 JSONL 性能日志记录。
- 本地成就和自动检查脚本。

## 当前主要风险

- `player.gd` 仍是高风险协调脚本，新增功能应继续下沉到 `scripts/player/*`。
- `main.gd` 仍承担战斗主控，新增流程应优先放入 `scripts/game/*`。
- 角色构筑、祝福、技能、装备、角色面板和存档之间的数据边界需要持续验证。
- 大量特效命中大量敌人、同一批刷怪警告同时结束并实例化新怪、或长时间游玩中的自动存档/掉落物保存规模增长时，仍可能产生性能压力；自动保存战斗进度固定约 2 秒覆盖当前运行存档和备份，敌人/敌方弹幕/掉落物批处理默认启用，开发者模式小怪批量生成不受普通敌人运行时上限限制，无尽模式不会因低 FPS 自动降低普通敌人数量，设置读取、战斗 HUD 按键显示和刷怪成长评分已避免高频重建，复现卡顿时可短时开启 JSONL 性能日志，后续优化需要继续用同场景 p95 / p99 / max 帧时间、SavePeak、批处理峰值、CPU/core 证据和玩法等价计数作门禁；详细记录见 `12_性能优化与验证记录.md`。

## 后续重点

1. 继续验证 36 个质变的实战平衡；新增阈值时仍从现有技能构筑等级派生，不建立第二套等级。
2. 完善角色面板里构筑、祝福、技能、道具和数值的可读性。
3. 继续优化大量命中判定、特效触发和长时间游玩自动存档尖峰，并保持 benchmark / evaluator / feature flag 证据链先行。
4. 扩展小 Boss / Boss 奖励，但保持奖励逻辑模块化。
5. 主线模式暂不开放，但保留相关代码。

## 当前开发护栏

- 新增进度内容必须进入角色构筑、祝福、技能或装备模块。
- 技能构筑等级和待选质变必须动态派生，不新增重复存档字段或第二套进度资源。
- 运行代码入口命名必须反映当前构筑、祝福、技能、装备和奖励职责。
- 已删除的开局特性选择、构筑等级调度和旧混合发牌入口不得作为本地扩展点恢复。
- 新功能如果属于祝福，优先改 `player_blessing_system.gd` 和 `player_blessing_skill_state.gd`。
- 新功能如果属于奖励流程，优先改 `game/reward_flow.gd`、`player_reward_applier.gd` 或 `player_equipment_flow.gd`。

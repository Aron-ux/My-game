# 构筑、祝福与文案交互规范

> 本文描述当前已实施的三层固定二选一天赋：每技能在 Lv.3 / Lv.6 / Lv.9 各选择一次，路径如 `221` 由三个阶段 ID 派生。108 节点数值、144 路径逐条行为回归和实战平衡的验证边界见 `13_会议目标与三层技能天赋规划.md`。

## 当前规则

- 普通升级展示 4 张卡并选择 2 张。
- 前 3 张分别对应当前队伍的三个角色槽位；第 4 张为通用祝福。
- 每张展示中的卡在当次升级可单独刷新一次，刷新后保持原角色槽位或通用槽位。
- 角色构筑卡覆盖角色特性、普攻、登场技、大招、技能解锁和已解锁技能强化。
- 带 `requires_skill` 的强化卡只在对应技能已解锁后进入候选池。
- 每个角色有特性、登场技、普攻、两个主动技能和大招共 6 个独立技能构筑等级；等级由该技能的基础解锁状态与已获得构筑卡数量动态派生，与玩家等级、祝福等级无关。
- 单个技能构筑达到 Lv.3 / Lv.6 / Lv.9 时，依次触发该技能阶段 I / II / III 的专属二选一天赋；每阶段选择后另一项本局永久排除，后续阶段必须连续完成。
- 完整显示名按“原技能·阶段 I 节点·阶段 II 节点·阶段 III 节点”追加；HUD 短名使用最后一次选择的节点前 2 个汉字。稳定的 `role_id`、`skill_progress_id`、`talent_id`、`build_id` 和构筑计数不变，路径不单独保存。
- 天赋后的普通构筑卡继续使用原 `build_id`，但卡牌归属、标题和说明会按当前完整名动态投影，并明确伤害、范围、冷却、次数等强化如何作用于当前形态。
- 一次普通升级的处理顺序固定为：四选二原子应用 → 必要的祝福绑定 → 所有新触发的技能天赋按角色、技能、阶段顺序逐个二选一 → 下一次待处理普通升级。
- 角色绑定祝福现在三人共用，不按单个角色独立生效。
- 技能绑定祝福单独存储，用于技能解锁、技能进化和后续技能加成。
- I 级祝福和 II 级祝福独立刷新；II 级祝福不要求同名 I 级先到 Lv.3。
- 各级祝福独立获得和保存，不提供祝福合成入口。
- 祝福没有三次上限，可以重复选择；角色等级越高，高等级祝福刷新概率越高。
- 魔石及魔石祝福接口仍保留，但不进入当前普通升级的四选二主链路。

## 数据入口

- 角色构筑定义与发牌：`scripts/player/player_build_system.gd`
- 技能构筑等级、质变定义与选择：`scripts/player/player_skill_talent_system.gd`
- 祝福定义与普通升级委托：`scripts/player/player_blessing_system.gd`
- 技能解锁和技能祝福倍率：`scripts/player/player_blessing_skill_state.gd`
- 升级请求与刷新：`scripts/player/player_level_flow.gd`
- 应用入口：`scripts/player/player_upgrade_applier.gd`
- 角色面板展示：`scripts/ui/hud/character_panel.gd`

## 三角色技能天赋

当前共 18 个技能构筑单元、108 个天赋节点（每树阶段 I/II/III 各左右 1 项）；具体数值和说明以 `player_skill_talent_system.gd` 为唯一源头。下列名称为阶段 I 基线，阶段 II/III 的完整节点表见 `14_三角色完整三层技能天赋设计.md`：

- 剑士：特性“血战昂扬 / 最后的换防”；登场“长驱冲阵 / 回马护阵”；普攻“十字剑势 / 背身斩”；剑刃风暴“随身风暴 / 驻地风暴”；月牙剑气“月返 / 满月重刃”；大招“擒王 / 剑华”。
- 枪手：特性“清场猎手 / 侵入猎场”；登场“聚焦礼炮 / 封锁礼炮”；普攻“破甲重弹 / 三连点射”；散弹“机动弹幕 / 延迟引爆”；无限装填“轴线贯穿 / 双轨齐射”；大招“线列轰炸 / 广域覆盖”。
- 术师：特性“奥能接力 / 奥能终式”；登场“雷环归心 / 雷印点名”；普攻“奥术余震 / 三角术式”；梅塔领域“领域转移 / 领域坍缩”；波涛汹涌“四向潮涌 / 逆潮回响”；大招“星落锁定 / 三星阵列”。

只持久化已选天赋 `role_special_states[role_id].skill_talents[progress_id] = [stage_1_id, stage_2_id, stage_3_id]`；旧单个 `talent_id` 自动迁移为阶段 I。技能构筑等级和待选队列均由现有构筑状态重建，不重复存档。

天赋后的升级遵循“先计算原构筑强化，再计算阶段 I 形态、阶段 II 战术、阶段 III 终局特性”：

- 分裂、追加、返回、双轨、跟随、坍缩和锁定类质变都继续读取原技能的构筑计数，不建立 144 套路径专属卡池。
- “血战昂扬”会由“骑士荣耀持续时间”构筑同步延长；“最后的换防”会继承战意治疗构筑提高救回生命，并继承骑士荣耀持续构筑提高强制登场后的无敌时间。
- “领域转移”的固定减伤只在术师持有领域阶段生效，转移后仍不提供减伤；“领域坍缩”的爆发继承领域伤害、范围和减速构筑，但不把固定减伤换算为爆发伤害。
- 天赋后的升级摘要由 `player_skill_talent_system.gd` 中 108 个 `talent_id` × 所属技能精确 `build_id` 的 270 条结构化映射生成，不再从自由文本或“伤害/范围”等粗轴猜测；运行时效果仍以原技能实际消费构筑数值的位置为准。不得只改卡牌文字而不验证实际技能读取路径。

## 当前祝福

- 神赐：最大生命。
- 祷告：技能冷却缩短。
- 破阵：技能范围。
- 恩典：大招能量回复。
- 贪婪：攻击命中时按概率回复最大生命值的 1%，每秒最多生效 1 次。
- 乘风：移动速度。
- 潮雨：持续性技能持续时间。
- 焰阳：造成伤害。
- 再演：连段技能额外连击。
- 幻影：闪避。
- 不屈：减伤。
- 戏法：数量技能额外数量。

## 技能解锁原则

- 当前角色构筑池包含直接技能解锁卡。
- 现有祝福配方检查仍可触发技能解锁和进化；这与直接解锁卡暂时共存，后续规则由源头统一。
- 一张 II 级祝福按三张 I 级祝福计算。
- 角色绑定祝福可以被三名角色共同用于解锁。
- 技能绑定祝福只能用于对应技能的解锁、进化或加成，不要被角色通用属性吞掉。
- 当技能解锁或进化会锁定/消耗配方祝福材料时，界面必须弹出提示，说明技能名称和被锁定的祝福材料。

## UI 交互

- 升级菜单展示构筑四选二，不再弹出独立的开局英雄特性选择。
- 三张角色构筑卡和一张通用祝福卡必须保持固定槽位语义。
- 玩家选满两张后统一确认；重复点击已选卡可取消选择。
- 每张卡的单卡刷新按钮当次使用后禁用。
- 技能天赋菜单固定展示当前技能、当前阶段的 2 张卡，只选 1 张且不提供刷新；选项标题为“基础名 · 阶段 N · 节点名”，并提示另一项本局不可选。
- 升级触发后的发牌会延后到下一帧并先暂停战斗；选择升级、祝福绑定或技能奖励后，HUD 完整刷新、战斗存档和连续待处理升级也会延后到后续帧处理，避免确认前后出现同帧卡顿；即时战斗数值仍会先用轻量 HUD 数据刷新。
- 角色面板的技能构筑页使用“6 技能选择器 + 当前技能三阶段左右树”；鼠标指向、键盘聚焦或点击技能都会立即切换详情。路径显示 `---`—`222`；每阶段显示真实的 Lv.3 / Lv.6 / Lv.9 门槛与已选、本局未选、待选或锁定状态。
- 每棵树下方单独列出由稳定 `build_id` 计数派生的普通构筑及重复次数；质变后使用投影名称、投影构筑文案和统一的后续强化说明，普通构筑不得画成天赋节点。
- 角色面板的祝福账本按三角色共享的角色祝福、按技能类型生效的技能绑定祝福分组，完整显示 I—IV 已持有阶数、当前效果和作用域；只查看祝福，不提供合成操作。
- 小 Boss 奖励展示装备或其他当前奖励。
- 祝福材料被技能配方锁定时，战斗界面显示短暂弹窗；材料仍保留自身数值加成，但不能再重复用于其他技能配方。
- 开发者模式添加祝福时，祝福列表显示的是“可继续用于选择/配方的可用计数”；角色绑定祝福按三人共享后的当前数计算。
- 开发者模式可直接授予任一阶段节点、替换阶段并清除后续阶段，或构造 `111`—`222` 路径；系统会补足所需技能解锁和构筑等级。

## 文案规则

- 直接说明玩家选择后发生什么。
- 避免空泛名词；文案只描述当前祝福、技能、装备和奖励。
- 数值说明要和 `player_blessing_system.gd` 中的实际数值同步。
- 技能绑定祝福要明确写出作用对象，例如“持续性技能”“连段技能”“数量技能”。
- 已选质变后，构筑卡必须写清强化作用于哪一段、哪一发、哪一轨或哪一阶段，以及质变保留的倍率；不能继续只写笼统的原技能名。

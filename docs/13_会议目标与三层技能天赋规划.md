## 二、三层固定二选一技能天赋（历史提案）

### 2.1 当时的设计合同

- 3 个角色 × 每角色 6 个技能构筑单元，共 18 棵树。
- 每棵树在技能构筑 Lv.3 / Lv.6 / Lv.9 各进行一次固定二选一，形成 108 个节点和每技能 8 条、合计 144 条局部终态路径。
- 路径如 `221` 只表示三阶段左右选择，不代表递归分叉子树。
- 普通四选二先结算，再追加旧技能节点选择；普通构筑继续使用稳定 `build_id`。
- 完整内容、名称、继承和当时的验收假设保存在 `docs/14_三角色完整三层技能天赋设计.md`。

### 2.2 基准提交与历史方案的分界

旧数据仍存在于 `player_skill_talent_system.gd`，开发者列表和部分旧 smoke 也仍能看到节点/路径，但基准提交的正式玩家链路不消费它们：

- `_build_offer_for_choice()` 固定返回 `{}`；
- `get_selected_talent()` / `get_selected_talents()` 返回空；
- `has_talent()` 固定返回 `false`；
- 存档规范化清空 `skill_talents`；
- 角色面板已移除三阶段左右树。

基准提交的正式规则改为：玩家等级达到 3 的倍数时累计一次 `pending_level_talent_choices`，先选剑士/枪手/法师，再从该角色最多 3 张合格 `LEVEL_TALENT_DEFINITIONS` 候选中选 1 张。42 条可发放定义组成 21 个 `_1` / `_2` 互斥组，保存于 `level_talents` 和 `level_talent_group_locks`。现行规则仍须回到 `04`、`08` 和源码核对。

### 2.3 若要重新启用旧方案

必须作为新的设计变更重新评审，并同时完成：

1. 明确它是替换还是并存，禁止出现两套无边界正式成长。
2. 恢复并测试玩家待选、发牌、应用、运行时读取和继续存档。
3. 定义旧档迁移、当前 `level_talents` 去向和互斥关系。
4. 恢复角色面板/HUD 可读性并删除误导性开发者入口。
5. 重新建立全路径行为、性能和平衡证据；旧 smoke 只能作为历史参考。

### 2.4 历史工作量基线

以下估算只用于理解当时方案的内容规模，不是当前路线图或发布日期承诺：

| 历史范围 | 粗略工作量 |

## 三、会议目标台账

> 本章的实现对照是整理提交 `478ead1` 时的非权威快照，用于说明会议目标后来发生过什么，不持续跟随实现。当前状态只查 `08_当前实现状态与后续重点.md` 和 `ROADMAP.md`。

### 3.1 角色 C 面板

会议目标：

- 显示当前角色的普攻和各技能获得过哪些强化。
- 显示角色获得的详细祝福。
- 修正生命、移动速度、攻击力等属性文本。
- 移除旧“三合一祝福”区域。
- 功能优先于 UI 美化。

基准对照：`[部分完成｜天赋账本缺失]`

- 角色面板展示三角色、实时核心属性、阮石/装备，并使用“技能构筑 / 祝福账本”双页签。
- 技能构筑页提供 6 技能选择器、普通构筑等级、具体构筑卡和重复次数；旧三阶段左右树已删除。
- 祝福账本按团队共享角色祝福与技能绑定祝福分组，展示 I—IV 已持有次数、当前效果、作用域与技能关联。
- 角色面板尚未展示当前真正生效的 `level_talents`，底部“查看天赋树”提示也仍待清理。

限制：

- 面板不能用旧 `skill_talents` / `get_display` 链代替当前等级天赋账本。
- 新账本应直接读取 `level_talents` 与互斥组，并与普通构筑列表保持视觉分离。

会议依据：00:01:32—00:02:08、00:20:13—00:21:09。

### 3.2 普通 Build、祝福与额外天赋菜单

基准对照：`[普通升级完成｜天赋规则已替换]`

- 普通升级固定为三张角色构筑卡加一张通用祝福卡，四选二；每张展示卡可以单独刷新一次。
- 当前额外天赋不再读取单技能构筑节点，而是在玩家等级达到 3 的倍数后进入“选角色 → 角色内最多 3 选 1”。
- 等级天赋详情卡位可各刷新一次；角色入口不刷新。
- 42 条可发放定义按 21 个互斥组组织，`_1` / `_2` 是替代项，不是先后层级。

仍需处理：`[待设计／待验证]`

- 当前等级天赋与普通升级、祝福绑定连续出现时的节奏密度。
- 21 个互斥组耗尽后的高等级行为。
- 高等级祝福是否出现过早，以及完整实战节奏。

会议依据：00:02:34—00:04:57、00:17:29—00:18:18。

### 3.3 三角色站场与后台身份

会议方向：

- 后台能力按角色定位区分，不要求三个人采用同一模板。
- 剑士可以在后台提供生存救援。
- 术师先站场准备，再把能量或大招收益带到后台。
- 枪手倾向纯站场输出。

基准对照：`[部分完成｜存在差异]`

- “最后的换防”运行时代码仍在，但只由已停用的旧 `has_talent("swordsman_trait_last_guard")` 查询，普通玩家当前不可获得；不能作为现行剑士后台救援能力计入。
- 当前剑士可通过等级天赋“战意 I”让后台剑士以折算概率/回复参与站场角色战意触发；法师已有奥法盈余、奥数充能、能量同步和当前等级天赋强化。
- 三个角色脚本仍保留 `perform_background` 实现，但全局周期性后台攻击调度当前直接停用；这些遗留实现不等于正式玩法正在提供后台普攻。

基准对照时沿用的决策：`[已决]`

- 枪手继续维持“无周期性后台普攻”，通过站场火力、命中回报和换人后接管战场建立角色差异。
- 用站场收益、后台收益和切换收益三项预算检查三角色差异，避免所有角色最终都变成后台自动输出。
- 后台能力调整不得破坏“普攻 < 切人 < 大招”的价值顺序。

会议依据：00:12:08—00:13:46。

### 3.4 角色切换与换位能量

会议确认：

- 普通切换不采用旧 7 秒冷却，只保留短防误触冷却。
- 未满能量时仍可普通切换，不消耗部分能量，也不触发入场技。
- 前台角色满能量时切换会清空其能量，并触发新站场角色的入场技；满能量不是普通切人的前置条件。

基准对照：`[已完成｜仍需规则说明]`

- HUD 已显示切换能量和切换冷却，当前角色切换保留很短的安全窗口。
- 当前代码会在切换时检查离场角色能量：满能则清空并触发入场技，未满则只完成普通切换。
- 基础冷却下限为 0.5 秒，切换无敌为 0.1 秒；退场技由 `EXIT_SKILLS_ENABLED=false` 全局停用。
- “最后的换防”消费满换位能量的代码仍在，但当前旧天赋查询恒假，普通玩家不可达。

下一步：

- 在角色面板和 HUD 说明“离场角色满能 → 新角色入场技”的归属，避免玩家误以为能量属于待切入角色。
- 修正移动教学仍宣称触发“退场技和登场技”的错误文案。
- 继续用 smoke 锁定能量获得、清空、入场技、短防抖和致命救援优先级。

会议依据：00:18:23—00:20:01。

### 3.5 小 Boss、Boss、装备与一次性道具

基准对照：

- `[已完成]` 小 Boss 已有装备/训练奖励流程，装备归属单个角色，并可在角色间转赠。
- `[部分完成]` Body / Combat / Skill Core 的奖励应用代码仍在，但当前最终 Boss 菜单只提供结束本局的空白继续选项，三种 Core 没有接入正式奖励菜单。
- `[待设计]` 明确最终 Boss 是重新接入 Core，还是改为单角色天赋卡、多人分别提升或团队奖励。
- `[待设计]` 任务式装备：累计击杀、指定技能击杀等条件完成后强化技能。
- `[待设计]` 一次性道具：暂停敌人、暂停刷怪等。

约束：

- 普通装备以数值为主，不默认承担大型技能机制改造。
- 大 Boss 的“多人升天赋”必须明确是多人各选一次、通用奖励，还是新的团队奖励类型，不能和“只有通用祝福全队共享”混用。
- 奖励继续走现有 `reward_flow`、装备和玩家奖励应用模块，不建立平行入口。

会议依据：00:05:03—00:07:20。

### 3.6 无尽模式外循环、阮狗、经济与铁匠铺

会议目标：

- 一局结束后应有局外资源或长期进度。
- 怪物可以掉落“骨头”等任务物，由阮狗提供任务并奖励装备或技能相关内容。
- 已通关内容可以反复刷资源、等级或装备。
- 铁匠铺应成为稳定消耗口。

基准对照：`[首版闭环已完成]`

- 无尽营地、阮狗对话、铁匠和通用交互链路已经存在。
- 无尽怪物现会掉落唯一首版局外资源“骨头”：普通怪 1%，精英 1，小 Boss 3；拾取后立即持久化，最终 Boss 的 8 骨由层级结算直接发放。
- 阮狗提供雷、冰、毒、炎、烈五石；五条等级永久、无限、线性费用成长，全队同一时间只装备一颗。
- 五石只修改直接普攻命中；雷石每次普攻事件只连锁一次，炎石对每个被直接普攻击杀的敌人触发一次按死者最大生命计算的范围爆炸，冰/毒/烈对不同直接命中目标生效，派生伤害不递归。
- 雷石已有连线和命中爆发，炎石已有橙红死亡爆炸环和范围命中爆发，毒石已有施毒爆发，冰/烈复用状态反馈；模式上下文会在进入战斗时正确加载当前无尽档案。
- 旧四难度已替换为 N1→N∞：N1 对齐原简单，N11 对齐原地狱；生命/伤害继续线性增长，其余高风险和性能轴在 N11 封顶。
- 每层 Lv.1 重开并固定 12 分钟；最终 Boss 后直接结算固定 8 骨、首通 `5 + 3N` 骨与 N+1 解锁，清除局内构筑返营，不再发同局技能奖励。
- HUD、角色面板、无尽档案迁移、`run_tier/run_id` 继续档、幂等奖励、成就和开发者任意 N 层测试已经同步。

后续验证目标：`[待实战数据]`

1. 统计每局骨头产量、五石装备率与平均等级，验证 `1%` 掉率和 `5 + 3L` 费用。
2. 验证高等级雷石目标上限、炎石死亡爆炸比例、冰石控制上限、毒石三层和烈石易伤对长局性能与强度的影响。
3. 在该闭环稳定后，再给铁匠铺一个明确职责；购买或合成二选一。
4. 在有数据前不增加金币、品质、随机词条、每角色独立石槽或多石同时生效。
5. 记录 N1/N3/N6/N11 的到达等级、死亡时间和通关率；只有低层开局重复感被证实时，才评估一次固定开局选择，不继承局内等级。

会议依据：00:07:21—00:11:42、00:15:59—00:16:52。

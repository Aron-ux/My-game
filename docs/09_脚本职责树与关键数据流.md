# 脚本职责树与关键数据流

## 战斗主控

- `scripts/main.gd`：战斗场景主控和 flow 装配。
- `scripts/game/game_scene_wiring.gd`：创建并连接 HUD、升级 UI、暂停菜单、角色面板等 UI。
- `scripts/game/game_hud_flow.gd`：把战斗状态投影到 HUD。
- `scripts/game/game_character_panel_flow.gd`：角色面板打开、关闭和暂停规则。
- `scripts/game/blessing_unlock_notice_flow.gd`：技能解锁/进化消耗祝福材料时的短提示弹窗。
- `scripts/game/reward_flow.gd`：升级、祝福绑定、当前玩家等级天赋、小 Boss 奖励和最终奖励流程；它是连续奖励菜单的唯一调度者。
- `scripts/game/enemy_spawn_flow.gd`：波次刷怪和刷新警告。
- `scripts/game/enemy_defeat_flow.gd`：敌人死亡后的奖励、成就和 Boss 流程。
- `scripts/game/difficulty_profile.gd`：从 N1 简单锚点与 N11 地狱锚点生成无尽层级数值。

## 玩家模块

- `scripts/player.gd`：玩家节点协调层。
- `scripts/player/player_build_system.gd`：角色构筑定义、四选二发牌、单卡刷新和构筑应用。
- `scripts/player/player_skill_talent_system.gd`：当前玩家等级天赋定义、每 3 级待选队列、三角色入口、角色内最多三张合格候选、技能解锁前置、互斥组、单卡替换、选择校验和存档规范化。旧 18 树/108 节点、名称/路径投影仍在文件中，但正式队列、应用和查询接口已停用。
- `scripts/player/player_blessing_system.gd`：通用祝福定义、发牌委托和应用。
- `scripts/player/player_blessing_skill_state.gd`：祝福驱动的技能解锁和技能倍率。
- `scripts/player/player_blessing_skill_bridge.gd`：玩家节点上的祝福查询、绑定选择和技能事件提示桥接。
- `scripts/player/player_level_flow.gd`：升级请求、构筑发牌/刷新和小 Boss 奖励入口。
- `scripts/player/player_upgrade_applier.gd`：升级/奖励分发器。
- `scripts/player/player_equipment_flow.gd`：装备奖励、角色持有、转赠和装备数值。
- `scripts/player/ruan_stone_system.gd`：无尽档案中的骨头、五石等级、线性升级费用、装备校验和效果数值。
- `scripts/player/player_ruan_stone_flow.gd`：识别三角色直接普攻事件，结算连锁、减速、毒伤、按死者最大生命计算的死亡爆炸和易伤，并阻止派生伤害递归触发。
- `scripts/player/player_skill_cooldown_flow.gd`：技能栏槽位数据，支持当前角色与指定角色的冷却槽构建。
- `scripts/player/player_timer_flow.gd`：玩家运行时计时器、临时 buff、技能冷却更新和开发者无冷却清理。
- `scripts/player/player_authored_effects.gd`：带动画场景的技能特效创建、播放、复用和释放。
- `scripts/player/player_effect_primitives.gd`：线条、圆环、爆发、护盾、文字等轻量特效创建、复用和释放。
- `scripts/player/player_run_save_state.gd`：运行中存档。
- `scripts/player/roles/*_role.gd`：三名角色普攻和角色差异。
- `scripts/abilities/*_ability.gd`：祝福技能的独立行为。

## UI 模块

- `scripts/level_up_ui.gd`：升级和奖励菜单。
- `scripts/hud.gd`：战斗 HUD。
- `scripts/ui/hud/character_panel.gd`：角色面板、普通技能构筑、祝福和道具展示；当前未投影 `level_talents`。
- `scripts/ui/hud/combat_skill_bar.gd`：底部技能栏；默认使用旧版居中技能栏，也可按 `gameplay/hud_layout` 切换为三行队伍状态栈，固定展示 Q / 当前 / E 三个角色的 HP、MP 和 6 个技能冷却槽。
- `scripts/ui/components/*`：卡片、悬停详情和通用 UI 组件。

## 升级数据流

`player.gd`
-> 获得经验并满足升级条件
-> `player_level_flow.build_blessing_upgrade_options`
-> `player_blessing_system.build_offer_for_owner`
-> `player_build_system.build_offer_for_owner`
-> `level_up_ui.gd` 展示三张角色构筑和一张通用祝福
-> 玩家选择两张
-> `player_upgrade_applier.apply_upgrade`
-> `player_blessing_system.apply_option` 分发角色构筑或祝福
-> `player_level_flow.handle_reached_level` 在玩家等级为 3 的倍数时累计 `pending_level_talent_choices`
-> `reward_flow.gd` 先处理全部祝福绑定，再展示待选等级天赋
-> `player_skill_talent_system.build_next_offer` 生成剑士/枪手/法师三个入口，各入口内最多 3 张合格候选
-> 玩家进入某角色并选择 1 张；候选卡位可各刷新一次
-> `player_skill_talent_system.apply_option_with_result` 写入该角色 `level_talents` 与互斥锁，并消耗一次 pending
-> 所有待选等级天赋完成后，再保存并恢复下一次普通升级

## 祝福技能数据流

祝福选择
-> `player_blessing_system.gd` 记录角色祝福或技能祝福
-> `player_blessing_skill_state.gd` 检查技能解锁与进化，并在锁定配方材料的事件中写入 `material_lines`
-> `player_blessing_skill_bridge.gd` 处理绑定选择队列、战斗文字和 `blessing_skill_event_announced` 信号
-> `blessing_unlock_notice_flow.gd` 显示“祝福材料已消耗”短提示
-> `player_skill_cooldown_flow.gd` 生成技能栏槽位
-> 对应 `scripts/abilities/*_ability.gd` 在战斗中触发

## 小 Boss 奖励数据流

小 Boss 死亡
-> `enemy_defeat_flow.gd`
-> `reward_flow.gd`
-> `player_level_flow.get_small_boss_reward_options`
-> `player_equipment_flow.get_active_reward_options`
-> `level_up_ui.gd`
-> `player_upgrade_applier.apply_upgrade`
-> `player_equipment_flow.apply_equipment_reward`

## 骨头与阮石数据流

敌人最终死亡
-> `enemy_drops.gd` 按无尽模式和敌人类型生成骨头拾取物
-> `player_survival_flow.gd` 吸附、收集并立即更新无尽档案
-> 阮狗收藏面板调用 `ruan_stone_system.gd` 获取/升级/装备
-> 战斗开始由 `game_story_context_flow.gd` 把当前无尽档案投影到玩家运行时
-> 三角色普攻使用显式基础攻击事件来源进入 `player_damage_resolver.gd`
-> `player_ruan_stone_flow.gd` 对一次事件去重并结算当前唯一装备石头

## 无尽 N 层数据流

营地传送门
-> `endless_tier_overlay.gd` 只允许选择 `N1...最高通关+1`，有运行档时锁定为继续该层
-> `save_manager.gd` 写入 `selected_tier`
-> `game_story_context_flow.gd` 生成当前 N 层难度并创建 `run_id`
-> `run_save_flow.gd` 保存 `run_tier/run_id` 与本层局内构筑
-> 12:00 最终 Boss 死亡后 `enemy_defeat_flow.gd` 请求结算
-> `save_manager.gd` 以 `last_rewarded_run_id` 幂等发放固定/首通骨头并推进 `highest_cleared_tier`
-> `reward_flow.gd` 显示单一返营确认，当前运行档被清除

## 存档数据流

`main.gd`
-> `save_manager.gd`
-> `player_run_save_state.gd`
-> 保存角色状态、祝福状态、技能祝福、当前等级天赋、互斥锁、待选次数、持续技能运行态、装备和战斗进度。

读取运行中存档时，`player_run_save_state.gd` 先恢复角色列表、装备、属性训练和祝福状态，再按最终角色最大生命值归一化 `role_health_values`。当前等级天赋从 `role_special_states[role_id].level_talents` 恢复，互斥锁会由已选项补全/规范化；活动选择上下文只保留重建候选所需字段。旧 `skill_talents` 统一清空。

能力运行态使用 `ability_runtime` 的六个技能 ID 保存并兼容旧扁平键。六个能力均保存施放天赋快照；剑刃风暴、无限装填和梅塔领域恢复计数与活动实例，月牙剑气弹体和散弹场按序列化状态重建。现有通用玩家 `Bullet` 节点及已排队 scheduler 回调不保存，故读档会丢失潮涌飞行波和尚未执行的延迟回调。骨头、阮石和最高 N 层属于无尽档案，不在玩家运行存档重复保存；本层玩家构筑及尚未拾取骨头只存在于 `run_tier/run_id` 对应的继续档。

## 开发护栏

- 新祝福先改 `player_blessing_system.gd`。
- 新祝福技能先改 `player_blessing_skill_state.gd`，再加 ability。
- 新奖励先判断是 `player_reward_applier.gd`、`player_equipment_flow.gd` 还是 `reward_flow.gd`。
- 新 UI 不直接堆进 `main.gd` 或 `player.gd`。
- 升级数据流以当前四选二构筑链路为准；后续技能解锁和构筑规则跟随源头。

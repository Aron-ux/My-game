# 最终 Boss 全阶段弹幕优化

基准提交 `b36bec9`，工作分支 `feature/polluted-magic-stone-danmaku`。本次覆盖护盾期、破盾后的三条血、基础攻击、全部六套演出及收尾。保留弹量、发射时序、伤害、寿命、轨迹、碰撞范围、远处弹丸原有更新时间、阶段规则及四秒平息。

## 实现

- 紫色/紫黑色球弹的柔光、描边、球体、亮芯改用四层 MultiMesh 绘制，共享同一份实例数据；仍使用原半径 8、20 边圆形几何及原来的层级、尺寸、配色。着色器分别计算四层外观，未改成低分辨率贴图。剔除边界包含最大柔光半径。
- 每颗弹丸保留模拟、存档和命中节点，游戏内不再为新球弹创建四个独立绘制节点。其余敌方弹种仍使用原外观。
- 对象池复用原实例位置和绘制顺序。回收时将对应实例设为零面积，避免残影；不因回收少量弹丸而移动全部实例。只提交发生的运动/透明度变化；旧实例槽耗尽或树顺序改变时才整理，保留原弹丸间透明叠加顺序。绘制存储为活动容量 5120 加对象池 1024，活动弹丸上限仍为 5120。
- 内置敌弹在批处理循环中直接调用已知接口，保留其他类型的兼容入口。共享一次批处理内的玩家位置与受击范围查询，每次命中调用伤害逻辑后立即失效，避免玩家移动、切换或范围改变后继续使用旧数据。
- 新弹丸跳过 `_ready` 中随后会被正式配置覆盖的默认初始化，避免重复登记及构造未使用的默认外观。普通敌弹及分裂弹仍通过原生成预算。

## 全阶段同次对照

Godot 4.6.2 / Windows / RTX 4070 SUPER / OpenGL Compatibility。高压力系数 1.65、固定随机种子、每个场景预运行 6 秒（过载 9 秒）、再采样 240 帧，模拟步长 1/60 秒；关闭测试窗口 VSync 和 FPS 上限。每一场景在同一进程内先跑旧版，再跑优化版；测试时没有并行运行其他基准。

旧版弹丸脚本和场景直接取自 `b36bec9`，仅将自身场景的资源路径改到隔离副本，其余逻辑及绘制不修改。两侧使用相同 Boss 编排和目标，通过原通用调度或新调度运行。隔离副本保存在本机 `.omx/boss-performance/reference_bullet.*`。

## 验证入口

- `boss_projectile_render_smoke.gd`：Vulkan 与 OpenGL 实际绘图，逐像素比较原 Polygon2D 与新批量绘制；涵盖不同颜色、尺寸、旋转、重叠、淡出、对象池复用和读档。两个后端的 8 位颜色通道最大差值均为 1，未删除几何或视觉层。生产生成路径只留下一个隐藏的兼容图形子节点。
- `boss_projectile_renderer_lifecycle_smoke.gd`：真实批处理提交位置、池槽复用、普通敌弹复用、直接删除后整理、保存恢复、清弹及新阶段再次生成。图形实例数据回读在实际 Vulkan 上验证；headless 的 Dummy 渲染器不返回实例变换。
- `enemy_projectile_frame_context_smoke.gd`：对照共享查询和原逐弹查询的命中顺序、移动、受伤后位移及受击范围变化，并检查不同目标不会共用错误的几何数据。
- `boss_danmaku_stress_smoke.gd`：使用正式批处理和绘制登记路径，在压力系数 0.90 / 1.65 下各模拟 270 秒，覆盖六主题、十二弹路、跨周期回收、实例整理和死亡清理；两档均通过，峰值活动弹丸分别为 1258 / 2213。此项为 headless 逻辑回归，不作为实际绘图帧率。
- 同步执行 Boss 循环/收尾、伤害、护盾、属性、视觉、玩家/敌人存档、普通敌弹批处理、分裂预算及分裂射击等回归。日志位于 `.omx/boss-performance/regression/`。

# 技能悬停与选卡信息设计

保留原有弹出的四张竖向纸面卡牌。卡面帮助玩家比较“给谁、升到几级、本次获得什么”，下方详情解释具体规则与数值。战斗技能悬停展示“这个技能是什么、当前处于什么状态”。暗金用于整体框架和强调，原卡牌纸面、手绘边框、装饰与刷新按钮继续使用。

## 0. 决策摘要

[已定设计] 用户确认保留暗金基调，并两次强调保留原有四张卡牌形式；在查看基于实际卡牌重排的信息示意后，确认“可以，就按照你这样”。据此进入实现。

[源码事实] 四选二、单卡刷新一次、第二张选择自动提交保持原流程。新增的是信息层级、选择状态和详情布局。

[运行证据] 预览与实装图、生成提示词位于 [设计附件](../../design/ui-skill-choice-20261013/README.md)。概念图只约束布局，不作为数值权威。

## 1. 范围与约束

面向暂停选卡时需要比较收益的玩家，以及战斗中短暂查看技能的玩家。覆盖普通升级、新技能、技能 5 级天赋位、祝福、旧版居中 HUD 和三行队伍状态带。

1280×720 为逻辑基线，使用 Godot 原控件与已有美术。沿用现有暗金主题、纸牌场景和技能对象；不添加依赖，不修改成长概率、奖励队列、伤害规则或存档结构。

## 3. 玩家问题与成功标准

[假设] 玩家先读主要收益，再按需查看完整说明，比读一段同等字号的叙述更容易比较四个选项。角色归属与技能等级在卡面可见，可以减少“这张牌影响谁”的记忆负担。

视觉验收要求：首屏能识别归属、类型、等级变化和主要收益；查看一张牌时其他三张仍可见；长说明保留完整文本；深浅背景分别保证字色可读。理解速度与选择质量仍需真人试玩，截图和自动检查不能证明这些主观收益。

## 4. 状态与机制清单

- H 信息、M 决策：改变卡面顺序、详情位置、悬停延迟和选择标记；选择规则不变。
- K 身份、R 关系：读取角色 ID、技能 ID、技能成长 ID、祝福绑定与份数，明确作用域。
- V 数值、Q 时间、P 权限：读取等级、收益、冷却、自动/手动和待命状态；展示过程不授予奖励、不升级技能。
- E 存在、X 空间、C 控制：只重排现有 UI 控件与浮层；保留卡牌动画、技能栏拖动、右键切换模式和暂停规则。

核心机制：指向卡牌 → 约 0.18 秒后出现下方详情 → 比较说明与数值 → 按现有流程选择 / 取消 / 刷新。看详情无额外消耗，离开或切换奖励后关闭旧详情。

## 5. 链、环、网络与生态

信息链为“技能 / 祝福数据 → 只读展示字段 → 卡面摘要与详情 → 玩家选择 → 原奖励应用链”。显示层不另设成长状态，升级预览不采用给真实玩家加点再回滚的方式。

战斗栏快速刷新保留说明缓存，持续更新可见冷却。卡面、战斗说明和实际能力尽量复用已有数据；当前机炮和重炮的关键数值已与运行时 getter 共用。经济、敌人生态、掉落和角色强弱不在本轮变更范围。

## 6. 玩家体验视角

本轮直接改善可读性、注意力分配、决策依据与反馈。技能归属保留三人队伍的构筑身份，纸牌形式保留原游戏辨识度。

战术技巧、公平性、反制、重玩动机与角色叙事没有新增规则，属于间接体验假设；未用这轮布局改动声称战斗更平衡或更好玩。

## 7. 系统全景影响

| 范围 | 变化 | 保持 |
| --- | --- | --- |
| 选卡 | 归属 / 类型、等级、主要收益、次要变化、已选数量与标记 | 四张横排、两张生效、每卡刷新一次、原动画 |
| 新技能 | 能力摘要、完整能力说明、冷却与已有参数 | 解锁条件、技能 ID、实际学习流程 |
| 祝福 | 作用域、本阶持有份数的前后对照 | 各阶独立持有、原结算与效果 |
| 技能天赋 | 明示天赋位 I / II、效果尚未实装 | 5 级二选一、10 级获得另一个位 |
| 两种 HUD | 角色、等级、释放模式、状态、独立数值行；浮层放在栏上方 | 技能顺序、切人、右键模式切换、左键拖动 |
| 其余系统 | 不适用：没有规则调整 | 敌人、关卡、资源、存档、装备、成就、音频 |

## 8. 整局生命周期

初次学技能时解释能力；普通升级时强调本次增量；跨越里程碑时优先展示新增段数或天赋入口；祝福重复获得时显示份数增长。战斗中可快速查询等级和冷却。

Boss、死亡、结算、营地与重开流程不改变。连续奖励仍由原队列驱动，新一轮重建卡牌时清除上一轮悬停详情，防止旧选项残留。

## 9. 退化模式与边界

- 暂不为天赋占位或缺失成长说明编造收益。
- 长卡面优先保留主要收益和前两项次要变化；其余明确提示看详情。使用自然换行和可见省略，完整文案不被截成 32 个字符。
- 纸牌颜色不用于暗色详情正文，避免黑底黑字。
- 不将伤害倍率当作最终伤害，不重复乘上面板攻击力中已有的加成。
- 技能 5 级天赋位内容、机械师数值成长、全部技能的实时参数规范属于后续独立工作。
- 系统中文字体按平台回退；本轮验证环境为 Linux。最低窗口缩放已检查，跨平台字体外观尚未实测。

## 10. 综合发现

根因是“已有数据未被展示”与“源头说明不足”同时存在。卡面硬截断、等级字段不一致和字色继承属于显示缺陷；新技能简述不足、空天赋与缺失成长预览属于内容缺口。两者分别处理，避免用更漂亮的面板承诺不存在的效果。

## 11. 方案比较与外部参照

| 方案 | 结果 |
| --- | --- |
| 只增加原描述字数 | 仍会被硬截断，信息优先级仍不清楚 |
| 改成两行两列面板 | 不符合用户保留原四张卡牌的要求，不采用 |
| 原四张卡牌 + 卡面分层 + 下方详情 | 已确认并实装 |

参考解决方法，而非复制美术：

- **Brotato**：四个升级选项中直接显示可比较的收益，旁边提供当前状态。用于确认“选卡需要可比较的变化”，不引入全队三人的大属性表。参见 [升级界面截图所在评测](https://chromabox.com/blog/test-brotato-pc-le-jeu-qui-va-vous-donner-la-patate.html)。
- **Hades**：将主要能力和补充规则分层，关键词可以另行解释。用于避免把所有条件挤进第一段；本轮不新增术语字典。参见 [Supergiant 官方界面改进说明](https://www.supergiantgames.com/blog/hades-welcome-to-hell-update-patch-notes/)。
- **Dota 2**：技能信息应能指出数值、状态与强化来源。用于支持结构化说明和渐进展开，不照搬长公式或增加新按键。参见 [官方 Spring Cleaning](https://www.dota2.com/springcleaning2018/)。

这些是对参照的设计取舍，不是它们必然提升本项目体验的实测结论。

## 12. 决定与设计合同

已确认：四张原纸牌横排弹出，刷新钮保持独立；整体暗金、纸面深色文字；卡面顺序为角色 / 类型、技能名、等级变化、主要收益、次要收益。当前悬停用金色轮廓，选择另有勾选标记与顶部计数。

选卡详情位于卡牌和刷新钮下方。左侧讲效果及适用条件，右侧在数据可用时列参数或前后对照。技能悬停放在整个战斗栏上方，基础说明、数值、状态、操作提示分区。

第二张选择仍自动提交，无新确认按钮。按实际配置显示技能键与角色面板键，不抢占右键；查看信息不自动暂停战斗。没有存档迁移或永久设置新增。

若出现详情遮挡卡牌、正文无法读完、浮层信息过时或显示数值偏离运行时规则，应先修复显示合同，不能通过修改战斗数值去适配示意图。

## 13. 验证计划与结果

新增 `scripts/tests/skill_info_ui_smoke.gd` 验证：

- 20 个可学习主动技能都有能力摘要和冷却信息；
- 升级预览显示 3→4 及追加斩击 1→2，且不修改玩家成长状态；
- 祝福份数对照正确，预览不授予祝福；
- HUD 快速刷新保持描述与等级，可见冷却更新，移除技能关闭旧详情；
- 两种 HUD 的技能详情位于栏上方，待命角色有明确提示；
- 四卡选中标记、数值表容纳、浅色卡与暗色详情的字色隔离；
- 长祝福、全部角色升级预览、天赋位与 960×540 窗口缩放。

检查结果：`skill_info_ui_smoke`（无头与图形模式）、`level_up_scroll_reopen_smoke`、`player_skill_level_system_smoke`、`swordsman_skill_level_effect_smoke`、`mechanic_roster_smoke`、`mechanic_visual_smoke` 均通过。Godot 4.6.2 无头启动通过，8 张实装截图已归档；原剑士卡牌测试同步检查分层后的主要收益和详情注释，仍验证追加斩击的 60% 伤害说明。

这些检查只能确认覆盖范围内的布局及行为正确。完整一局的阅读节奏、鼠标往返负担和真人理解速度仍待试玩。

## 14. 实现交接

- `level_up_ui.gd`：沿用卡牌场景，增加信息分区、状态标签和下方详情位置；维护原选择、刷新与动画。
- `survivors_hover_detail.gd`：共享暗金文字与数值渲染，按字体度量估算高度，独立更新状态。
- `combat_skill_bar.gd`：缓存技能说明，绑定当前槽位与角色，更新可见冷却和模式。
- `player_build_system.gd` / `player_skill_level_effect_flow.gd`：提供本次收益、新技能说明和可用对照；没有预览时明确说明。
- `player_skill_cooldown_flow.gd`：复用能力对象说明，补角色、等级、摘要与冷却元数据。
- `player_blessing_system.gd`：只读计算本阶持有份数。
- 两个机械炮台能力：说明与发射复用同一伤害倍率 / 持续时间 getter，数学规则保持原值。

同步 `docs/04`、`docs/06`、`docs/08`、`DESIGN.md`、已知问题和 `CHANGELOG.md`；不扩展路线图或重写无关状态记录。

## 15. 决定记录

2026-10-13：用户确认普通升级、新技能、天赋和祝福一并考虑，保留暗金基调；随后明确保留原有弹出的四张卡牌。在基于实际原卡牌的示意图上确认实现。

剩余内容决策：技能天赋位具体做什么、机械师各技能的等级成长数值。它们不由本轮 UI 实现代替决定。

## 16. 实装后回顾

已从布局示意进入实际 Godot 控件，原卡牌、动画与选择流程继续工作。实际截图替代概念图作为实现证据。

概念图里的“120%→130% 伤害倍率”没有被照抄：剑士普攻基础倍率为 150%，实际界面分别显示本次增加 10 个百分点，以及等级伤害加成 +20%→+30%，避免把等级部分误认成最终倍率。完整实时数值表目前只覆盖可用数据，未声称全部能力完成实时计算展示。

本轮处置：保留实现；真人阅读测试、跨平台字体与完整一局验证继续作为体验验证，不视为自动检查已覆盖。

# 游戏设计评审：当前 Build 全景基线分析

> 方法依据：[`../15_游戏设计全景分析与评审流程.md`](../15_游戏设计全景分析与评审流程.md)。本记录用于锁定当前事实和讨论顺序，不代表玩法方案已批准。
>
> 后续状态：同一组合 PR 已对齐过期 smoke 替身并移除旧 108 节点断言，全量门禁已恢复为 `PROJECT_CHECK_OK`。下文对 `323c687` 的失败记录作为历史基线证据保留。

## 0. 决策摘要

### 一句话判断

当前 Build 已经有一套**能运行、能形成局内高潮的三角色 survivor-like 骨架**，但尚未形成一套同样清楚的玩家决策系统：切换、主动技能、成长、敌人反制和复盘各自存在，尚未共同证明“玩家为什么在这一刻切这个角色、做这个选择，以及为什么愿意立即再来一局”。

### 总体成熟度

- **架构清晰度：2/4，功能成立。** 入口、组合根、flow、存档和 HUD 投影基本可追踪；状态所有权仍集中在 `player.gd` / `main.gd`，奖励和角色面板跨边界读取。
- **核心玩法清晰度：2/4，功能成立。** 走位、自动普攻、离场角色攒能、满能登场技、角色独立大招已构成可玩链；敌人尚未明确要求轮转，六个可见技能槽与实际手动权限不一致。
- **爽感完成度：1/4，存在但弱。** 镜头、特效、入场爆发和大招有视觉高点，但缺少战斗 SFX，关键文字反馈又全局关闭，玩家难把高密度画面归因为自己的正确决策。
- **构筑与重玩：1/4，存在但弱。** 固定三角色槽、四选二、等级天赋互斥组能形成方向；普通构筑主要是线性重复，正式通用祝福只有 7 种，真正改变行为的 `level_talents` 无法在面板复盘。
- **验证成熟度：1/4。** 4 个 Python 门、3 个场景启动与常规 smoke 现已跑到 `PROJECT_CHECK_OK`，但仍没有图形长局、完整 Boss 结算、多 N 层或真实玩家证据。

### 当前最强玩点

```text
走位与瞄准
→ 当前角色按独特节奏自动输出
→ 伤害积累离场角色切换能量
→ 玩家判断何时 Q/E
→ 满能切换消耗离场角色能量
→ 新角色登场技形成短时爆发
→ 角色独立能量满后按 R 制造更大高潮
→ 升级选择改变下一轮输出、生存和轮转效率
```

这个结构的差异点不是“三个职业可以换”，而应是：**玩家通过三人的生命、距离、能量、登场技和大招，连续接管一个团队，而不是操控一个带三套皮肤的单角色。**

### 当前主要断点

1. 正式天赋池耗尽后仍会打开三张空角色入口，可把战斗锁在暂停奖励 UI。
2. 正式通用祝福只有 7 种；配方依赖的 legacy 材料不会被正式奖励生成器发出，所谓“直接解锁与配方双入口”对新档并不成立。
3. 教程承诺退场技与登场技同时触发，但运行时退场技全局停用。
4. 六个技能槽和 `1`—`6` 输入看似承诺手动技能，实际普通玩家只有天赋化“无限装填”可手动切换，其余主动技能自动触发。
5. 当前真正生效的等级天赋没有角色面板账本，旧“查看天赋树”提示仍在。
6. `12:00` 是最终 Boss 到场，不是结算时点；实际单局时长还包含 Boss 战。
7. 发布门当前为红，尚不能用“smoke 很多”替代完整可发布证据。

### 推荐结论

采用**最小稳定化路线**，暂不扩新货币、新职业、新 Boss 框架或复活旧 108 节点：

1. 先消除空奖励、不可达配方、错误教程和发布门红灯。
2. 再补当前状态的可查询性和关键事件反馈。
3. 只做一个战斗能动性实验：挑一个代表性主动技能改为明确手动时机，或保持自动但让敌人/资源产生可观察的切换理由；两者不要同时大改。
4. 记录角色站场、切换原因、能量浪费、天赋选择、死亡来源和重试行为，再决定内容扩张。

### 完成条件

本记录达到 `evidence_ready`：已锁定基准、当前链路、主要冲突、优先级、最小方向和验证假设。进入实现前仍需逐项批准设计合同。

### 架构判断

当前是“**行为已拆、状态和契约未拆**”：

- `main.gd` 已经主要充当组合根，`game_scene_wiring.gd` 也建立了清楚的接线边界。
- `player.gd` 仍同时持有成长、角色、资源、技能、装备、祝福、视觉缓存和临时状态；各 flow 通过 `owner.field` 动态访问，文件拆开了，但字段契约仍是隐式的。
- `reward_flow.gd` 是唯一调度者，但奖励会话状态散在 `reward_context`、Main metadata、Player 字段和 UI 当前上下文。
- HUD 大体消费投影；角色面板却直接读取 Player 私有方法并执行转赠命令，View、Presenter、玩法命令混合。
- 旧 108 节点通过空查询、`false` 和存档清空停用，却仍与当前等级天赋驻留同一运行模块和测试目录。

所以 Build **不是混乱到无法开发**，但也不适合继续叠加第三套成长、奖励或 UI 状态源。下一阶段应收窄既有边界，而不是引入事件总线、MVVM 或全新状态机框架。

## 3. 机制、链、环与爽感

### 3.1 持续操作链

```text
WASD 走位 + 鼠标/自动目标模式
→ 当前角色以职业攻击间隔自动普攻
→ 命中、击杀、治疗、能量与经验结算
→ 玩家继续调整距离和方向
```

优点：低输入负担，适合 survivor-like 长局；三角色攻击节奏明显不同。

风险：自动普攻和六个自动尝试技能把大量结果交给系统，玩家长期只剩走位、切换和 R。若敌人也不要求明确角色回应，玩家容易感到“画面很忙，但不是我打出来的”。

### 3.2 角色轮转链

```text
某角色造成伤害
→ 该离场候选角色自己的切换能量累积
→ 玩家观察三行状态/圆环
→ Q/E 切换
→ 未满：正常换人 + 新角色技能锁
→ 满能：消耗离场角色全部能量 + 新角色登场技
→ 0.1 秒无敌 + 0.5 秒以上切换冷却
```

它已经提供了风险—收益：现在换人能换距离、生命和角色适配；等满能再换能得到登场爆发，但要承受继续站场的风险。

断点在于：

- 教程把结果写成“退场技和登场技”，与实际规则相反。
- 能量属于离场角色，但教程与即时 HUD 的表达仍容易让人理解成“将登场者的能量”。
- 退场技和周期性后台普攻都停用，轮转更接近“积满后换人放入场技”，尚未形成前一角色铺垫、后一角色接力的完整 relay。
- 敌人目标和生态主要围绕当前 Player，没有证据证明某种敌人组合会显著提升某一角色或迫使换人。

### 3.3 高潮链

```text
命中/击杀/被动回复
→ 当前站场角色独立大招能量增长
→ 玩家保留或按 R
→ 扣除该角色能量
→ 大招演出、伤害与 2.5 秒角色锁
→ 返回普通战斗
```

R 是当前最可靠的手动高峰。剑士连续斩击、枪手弹幕、法师多轮轰炸有不同幻想和空间表现。

当前爽感可拆为五层：

1. **预备**：能量接近满、敌人聚集、Boss 输出窗。
2. **决定**：玩家按 Q/E 或 R。
3. **释放**：突进、雷环、弹幕、斩击、轰炸。
4. **结果**：击退、清场、生命恢复、状态变化。
5. **理解**：玩家知道“是我的何种判断造成结果”。

本 Build 的第 3 层较强，第 1、2 层成立但不够显性，第 4 层有画面，第 5 层最弱。没有战斗 SFX、切换 Banner 和普通 combat tag 又被全局关闭，导致“视觉强度”没有稳定转化为“控制感”。

### 3.4 成长链

```text
升级
→ 固定三角色构筑槽 + 一张通用祝福
→ 四选二，可逐卡刷新一次
→ 直接解锁或线性强化
→ 每到 3 的倍数，追加一次角色等级天赋
→ 先选角色，再从最多三张合格候选选一张
→ 同组另一方案锁定
→ 运行时通过 has_level_talent() 生效
```

优点：

- 每级都展示三人，角色不会因随机池完全消失。
- 四选二天然产生机会成本：两角色、角色+团队、或放弃某角色。
- 等级天赋按角色选入口，定向性强于普通随机卡；互斥组可以产生行为差异。

断点：

- 45 项普通构筑主要是可无限重复的线性数值，池会在技能解锁后扩张而不是收束，构筑身份容易被稀释。
- 当前只有 7 种正式通用祝福，长期随机变化窄于文档曾描述的 12 种。
- `direct unlock` 实际是唯一正式技能解锁路线；配方层的 UI、锁料和进化语义仍造成维护与认知噪音。
- 当前最有身份感的 `level_talents` 在选择后无法从角色面板查询，学习环在“效果生效”之后中断。
- 候选与单卡刷新使用状态不完整持久化，退出继续可重新生成候选，产品是否允许存档刷牌未定义。

### 3.5 局外循环

```text
本层战斗
→ 小怪/精英/小 Boss 掉骨头，拾取即永久保存
→ 最终 Boss 击败后结算固定与首通骨头
→ 解锁 N+1，返回营地
→ 购买/升级五种阮石，只装备一颗
→ 再进入更高或已解锁 N 层
```

这条循环已经具备明确货币、消耗口和层级目标，是当前最完整的长期动机。限制是永久成长轴较窄，N11 后多数压力轴封顶，只继续放大生命/伤害，后期容易从“适应新问题”退化为纯数值门。

## 4. 玩家体验十二视角

| 视角 | 当前表现 | 主要风险/机会 | 评分 | 置信度 |
| --- | --- | --- | --- | --- |
| 心智模型与可读性 | 基础键位清楚，能量、天赋、手动权限不清 | 教程错误、面板缺账本、关键详情依赖悬停 | 1/4 | 高 |
| 能动性与决策质量 | 走位、Q/E、R、四选二成立 | 主动技能大多自动，敌人不明确要求轮转 | 2/4 | 中高 |

| 反馈与感官编排 | 特效、镜头、预警和大招演出丰富 | 无 SFX；文字与 Banner 关闭；密度可能掩盖因果 | 1/4 | 高 |
| 节奏/张力/释放 | 3/6/9 分钟小 Boss、12:00 最终 Boss | 6:00 双峰；奖励暂停不是战斗内恢复窗 | 2/4 | 高 |

| 角色幻想/主题 | 剑士生存、枪手点杀、法师范围控制明确 | relay 只剩登场端，敌人生态未放大三人互补 | 2/4 | 中高 |

## 5. 整局生命周期

| 阶段 | 当前事实 | 体验判断 | 风险/待验证 |
| --- | --- | --- | --- |
| 进入前 | 选 N 层与阮石，可继续同层运行档 | 有明确长期目标 | 重试要经过营地/入口，摩擦量待实测 |
| 前 30 秒 | 主要是 chaser，自动普攻和走位建立控制 | 低压学习合理 | 教程规则与正式切换不一致 |
| 0—3 分钟 | runner/shooter/swarm/brute/dasher 逐步加入 | 构筑种子与第一次角色适配窗口 | 首个行为天赋出现速度与可理解性待测 |
| 3:00 | 小 Boss 1，奖励暂停 | 第一次阶段考试 | 奖励是否放大已有方向未有数据 |
| 3—6 分钟 | 密度和危险怪继续提升 | 主循环成形 | 没有显式低压恢复段 |

## 6. 排序后的发现

### P0：发布与正式流程阻断

#### P0-1 天赋耗尽会形成空奖励锁

- **触发**：未解锁六个主动技能时，三角色约 15 个无前置主题组选完；下一次 Lv.48 触发。若全部 21 组选完，下一次 Lv.66 触发。
- **机制**：外层始终生成三张角色入口，内层候选都为空；RewardFlow 只检查外层数量等于 3，随后暂停并打开 UI。
- **后果**：玩家无法选择、无法消耗 pending、战斗保持暂停。
- **最小方向**：候选总数为零时不打开菜单并安全消费/终止该次 pending；无候选角色入口禁用并明确“已选完”。先定产品合同是跳过、转为普通奖励还是停止后续触发。
- **验收**：15 组与 21 组两个耗尽场景均无空菜单、无永久暂停，保存继续后仍可战斗。

#### P0-2 基线发布门为红（已解决）

- 提交快照的全量检查被两个 stale enemy smoke 替身的 SCRIPT ERROR 阻断；测试打印 `OK` 不代表通过。
- `player_blessing_system_smoke.gd` 还保留旧 108 节点对卡面的投影断言，与当前 `get_selected_talents()` / `has_talent()` 停用契约冲突。
- 当前工作树又缺少两个显示配置键，使配置门更早失败。
- **最小方向**：对齐两个测试替身，并将 blessing smoke 的旧投影断言降为明确命名的 legacy 迁移测试或删除；`project.godot` 属评审前已有改动，不在本任务自动覆盖，由其所有者确认意图。
- **验收**：4 个 Python 门、3 个场景与全部常规 GDScript smoke 到达 `PROJECT_CHECK_OK`；dense benchmark 仍单独跑。
- **解决记录**：组合 PR 已完成上述测试对齐，并在保留发布配置的干净分支上跑到 `PROJECT_CHECK_OK`。

### P1：核心承诺和正式规则断链

#### P1-1 技能解锁“配方双入口”是伪共存

- 正式奖励只发 7 种 `GENERAL`；主动技能配方依赖多个 `LEGACY` 材料。
- `direct unlock` 调用 `force_unlock_skill()`，成为新档唯一正式可达路线。
- **最小方向**：当前版本明确 `direct unlock` 唯一正式入口，把配方标成 legacy/开发者兼容；不要为了匹配旧文档重新开放一整套材料、绑定、锁料和进化平衡。

#### P1-2 教程教授不存在的退场技

- 教程写“触发退场技和登场技”，运行时 `EXIT_SKILLS_ENABLED=false`。
- **最小方向**：只改现有文案为“离场角色能量满时消耗其能量，触发新角色登场技”，不改教程流程。

#### P1-3 主动技能权限与 HUD 承诺不一致

- 六个技能均在 tick 中自动尝试触发；`1`—`6` 只有无限装填 I 可成功。
- **最小方向**：在未决定技能设计前，HUD 只给实际可手动槽显示数字键，自动技能标“自动”；无效按键不制造假权限。
- **设计问题**：项目要的是“低操作自动技能 + 手动轮转”，还是“至少每角色一个主动时机”？必须明确，不能靠 UI 含混过去。

#### P1-4 当前天赋无法查询与复盘

- `level_talents` 正式生效并保存，角色面板却只显示普通构筑与祝福，底部仍写旧天赋树。
- **最小方向**：复用现有技能构筑页追加只读等级天赋区，不新增第三页或新状态；按角色列出已选项、互斥组和被锁替代项。

#### P1-5 关键爽感缺少归因反馈

- 入场和大招有镜头/特效，但没有战斗 SFX，Banner 与普通战斗文字关闭。
- **最小方向**：不先建完整音频系统；先验证四个事件音：满能就绪、登场释放、大招释放、升级确认。声音须独立调音量，再根据玩家辨认率决定扩展。

#### P1-6 敌人生态尚未证明三角色轮转必要

- 敌人类型能改变走位和目标优先级，但没有证据表明会改变角色选择。
- **最小方向**：先记录不同敌人/组合下的切换率、站场分布和死亡角色，不直接添加硬克制矩阵。若数据仍显示单角色长期垄断，再用一个现有敌人做软反制实验。

### P2：节奏、重玩和维护风险

1. `12:00` 是 Boss 到场，不是总局长；难度文案与体验承诺必须统一。
2. 6:00 精英与小 Boss 同时排队，可能形成没有恢复窗的尖峰；先看死亡时间分布，再决定错开 30—45 秒或降低其中一个峰。
3. N11 后只有生命/伤害继续成长，长期容易成为数值门；先复用现有敌人组合变化，不新建词缀框架。
4. 一个最终 Boss、固定三个小 Boss 顺序对首轮学习有利，对长期重玩有限。
5. 死亡页只显示时间与等级；无尽模式直接返回营地，没有本局骨头、死亡来源、关键构筑、下一石头费用或快速重试信息。
6. 候选与逐卡刷新使用状态未完整持久化，退出继续可重刷；需要明确这是允许行为还是漏洞。
7. `player.gd` 状态袋、分散的 Reward 会话状态和角色面板直读 Player 扩大后续改动面。
8. 旧 108 定义、no-op 查询和 legacy smoke 降低维护者判断正式系统的信号质量。

### P3：延后项

- `_1` / `_2` 配合卡名 I/II 容易被理解成递进等级。
- 法师当前天赋摘要仍有“术师”残留。
- 手柄、焦点等价详情、文本扩张、减少闪烁与完整本地化没有运行证据。
- 占位/非商用 BGM 与部分美术在公开发布前仍须替换或清权。
- 不应在当前阶段新增分析平台、大测试框架、新货币、商店或恢复旧 108 节点。

## 7. 根因链

### 根因 A：核心承诺没有成为跨系统验收门

```text
三角色轮转被定义为差异点
→ 角色、入场技、能量、敌人、HUD 分别实现
→ 没有统一验收“敌人何时要求换人、玩家为何愿意等满能、结果如何确认”
→ 切换存在但不一定必要
→ 画面强度高于决策清晰度
```

### 根因 B：迁移以“封死旧接口”代替“删除旧权威”

```text
旧 108 节点不再作为正式成长
→ 定义、投影、开发者入口、部分 tests 留在运行区
→ 当前等级天赋又放在同一模块
→ 文档、UI、测试各自保留旧词义
→ 团队反复把存在误当可达，把局部通过误当正式链通过
```

### 根因 C：反馈主要投资在视觉释放，而非玩家归因

```text
大量特效、屏震、投射物和预警
→ 战斗文字与切换 Banner 为降噪而关闭
→ SFX 尚未建立
→ 玩家看到结果但不一定知道触发条件和来源
→ 爽感难转化为可学习技巧
```

### 根因 D：局内池和无限生命周期没有共同边界合同

```text
等级每 3 级无限排队
→ 候选按有限互斥组耗尽
→ 外层 UI 为固定三角色入口
→ 没有零候选终止条件
→ 高等级正式奖励不可完成
```

## 8. 三种方向比较

| 方向 | 做法 | 收益 | 成本/风险 | 结论 |
| --- | --- | --- | --- | --- |
| A 保持现状 | 继续加内容和数值 | 短期快 | 空奖励、伪规则、低归因与门红继续积累 | 不推荐 |
| B 最小稳定化 | 关正式阻断、统一一条解锁路、补账本/反馈，做单点能动性实验 | 最大化已有资产价值，风险可控 | 需要先做几项不显眼的修正 | **推荐** |
| C 全面重做 | 全技能手动、敌人克制矩阵、新 Boss、扩元进度、重构状态 | 理论上深度高 | 同时改变过多变量，无法知道何者改善 | 当前拒绝 |

## 9. 推荐设计合同草案

### 合同 A：正式成长

- 普通升级固定三角色构筑 + 一通用祝福，四选二，逐卡刷新一次。
- 每 3 级追加一次当前等级天赋；零候选时必须安全结束，不得打开空 UI。
- 当前正式主动技能解锁只来自角色构筑 `direct unlock`。
- 正式通用祝福池就是 7 种 `GENERAL`；legacy 祝福与配方不能出现在新档正式规则说明中。
- 当前天赋必须在角色面板可查询；旧 108 不复活。

### 合同 B：轮转与技能

- 切换能量属于离场角色；满能切换消耗离场能量，只触发新角色登场技。
- 退场技在关闭期间不得被教程、卡面或 HUD 承诺。
- 自动技能和手动技能必须在 HUD 上使用不同权限标记。
- 若轮转是核心，至少一个敌人压力、一个资源窗口和一个反馈事件要让玩家能回答“为什么现在切”。

### 合同 C：无尽生命周期

- `12:00` 是最终 Boss 到场；击败后才结算。
- 结算/死亡必须能形成下一局计划：至少显示本局骨头、最终等级、主要天赋/阮石和下一可执行目标。
- N11 以后先用已有组合和时间表创造变化，再考虑新规则引擎。

### 合同 D：技术边界

- 新玩法不再向 `player.gd` / `main.gd`增加无关职责。
- RewardFlow 继续是唯一奖励调度者，并集中清理/设置奖励会话状态。
- 角色面板逐步改为消费现有 payload/快照；不引入 MVVM。
- 旧 108 代码优先删除或移出运行模块，不再添加兼容层。

## 10. 最小验证计划

### 自动化先行

1. 天赋 15 组/21 组耗尽：无空菜单、无永久暂停、pending 行为符合批准合同。
2. 正式奖励可达性：从新档只调用正式生成器，所有被文档标为正式的材料和解锁都必须可达。
3. 面板完整性：注入三角色 `level_talents`，标题和锁定组可查询，旧“查看天赋树”文案不存在。
4. 教程真实性：教程文本不得在 `EXIT_SKILLS_ENABLED=false` 时声称退场技触发。
5. 修复两个 stale test double 后，全量标准检查必须到达 `PROJECT_CHECK_OK`。

### 图形短局

- 1280×720 下完成移动、攻击模式、普通升级、Lv.3 天赋、满能切换、R、C 面板、暂停与返回。
- 纯键盘读取大招、切换能量和一个可手动技能；重要信息不能只靠鼠标悬停。
- 验证四个关键事件音或等价反馈能在高密度画面中被正确辨认。

### 完整单局与最小遥测

至少一局 N1 从正式入口打到 `12:00` 后击败 Boss，再验证结算、删运行档、返营。记录：

- 到达 `12:00` 的等级与最终结算时长；
- 三角色站场时间、伤害占比、普通/满能切换次数；
- 离场角色满能等待时间与能量溢出；
- 主动技能触发次数、R 使用次数；
- 最终普通构筑、等级天赋、祝福和阮石；
- 死亡时点、伤害来源或 Boss 击杀时间；
- 本局骨头、下一石头费用、是否立即重试。

只有这些数据不能回答问题时，才增加更细事件日志。

### 玩家假设

| 假设 | 最小实验 | 成功信号 | 否定条件 |
| --- | --- | --- | --- |
| 修正文案后玩家理解切换能量归属 | 5 名新玩家完成教程后复述 | 能说出“谁的能量被消耗、谁放登场技” | 仍归给登场角色 |
| 权限标签可消除 1—6 试探 | 自动槽标自动，仅可手动槽显示键位 | 无效按键次数明显下降 | 仍不知哪些技能自动/手动 |
| 天赋账本改善构筑学习 | Lv.9 暂停后 30 秒定位任务 | 能指出一个当前天赋及被锁替代项 | 把普通构筑当等级天赋 |
| 一个明确手动技能提升能动性 | 同技能自动版/手动版短局对照 | 玩家能说明何时使用且操作负担可接受 | 只增加忙乱，不改变判断 |
| 6:00 双峰是合理高潮 | 记录多局死亡时间与主观公平 | 死亡可预判且有恢复方案 | 死亡集中且玩家不知如何反制 |

## 11. 开发组讨论顺序

必须按以下顺序定案，避免用内容扩张掩盖基础断链：

1. 天赋耗尽时：跳过、转普通奖励，还是停止后续天赋触发？
2. 是否批准 `direct unlock` 为当前唯一正式技能解锁规则？
3. 项目对主动技能的目标是“自动技能 + 手动轮转”，还是“每角色至少一个手动时机”？
4. 三角色轮转是核心必需解法还是可选风格？若是核心，现有哪个敌人先承担软反制实验？
5. `12:00` 是否正式定义为 Boss 到场，而非总局长？
6. 角色面板最低账本信息和死亡/结算页最低复盘信息是什么？
7. 发布门已恢复后，哪一局 N1 作为首个正式图形长局基线？

在以上问题批准前，暂停新增成长轴、配方材料、新 Boss 框架和旧 108 恢复工作。
